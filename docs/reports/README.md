# reports

Findings from a pass over something — an audit, a hands-on workflow review, a survey of libraries.
A report is **evidence and method**, not a worklist.

That distinction is the rule for this directory. When a report argues for work, the work leaves as
GitHub issues before the report is published; the report keeps why the problem is real and how it
was found, and the issue keeps the thing to do. A report carrying its own open to-do list is the
`CHORES.md` failure re-created one folder down — nobody reads it, and the item ages into a claim
that is no longer true.

[library-candidates.md](library-candidates.md) is the shape to copy: it says outright that a library
evaluation is not a work item, and correctly stayed a document.

The annotated table is in [`docs/README.md#reports`](../README.md#reports).
