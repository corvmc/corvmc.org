# Reservations

Status: ✅ List + book + pay

New reservation flow with conflict checking, in-app checkout. A booking is `confirmed` when it is made, however far ahead; the schedule-then-confirm step, its reminders and the unconfirmed sweep were removed (#2502). **`reservation.hard_hold`** is what makes a hold block a recurring series outright — set when a show holds the room, read only by `checkEventAndClosureConflict`. It replaced `booker_type = 'event_listing'`, which answered "was this created via a listing?" rather than "is this a show", so advertising a session would have upgraded its priority A member without the Practice space clearance sees a **First booking** block under the policy strip: the notice, and while an orientation role is set the tour length and that it is free (#2747). One booking form with a **For** field (#3029): Me, each band the member may book for, and Teaching for an active instructor; each books through its own remote and terms. A band booking shows on the member's list with the band's name. **Slot link** (#3410): `/member/reservations?date=YYYY-MM-DD&start=HH:MM&end=HH:MM` opens the reservation dialog on the member's own booking with that slot chosen, then drops the params. The values are a hint: each is applied once, only if the picker still offers it, and the booking submit validates as it always does. A malformed or stale link opens the dialog on the first bookable day. Not a pre-validated ticket, because the query string is client input (#3410).
