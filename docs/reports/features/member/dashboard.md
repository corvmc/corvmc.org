Quick links, this week's reservations (incl. band), credit balance widget, upcoming events, pending band invitation banner, a pending action for an owned band with no other members. While `user.emailVerified` is false, a one-line notice with a resend link (`VerifyEmailNotice`, shared with the account page) follows the bands cards; `getMemberDashboard` reads the flag from the user row, not the session, whose cookie is trusted for 60s. Seeded persona: `undecided@` **First reservation card** (`FirstBookingCard`, #3410): until the member has a reservation that is not cancelled (waitlisted counts, whoever it is for, keyed on `createdByUserId`), the dashboard offers up to 3 open 2-hour slots, one per day, each linking to `/member/reservations?date=&start=&end=`. Peak starts (15:00 up to 17:30) come first; with none open in the booking window, any open start. `getMemberDashboard` computes them through `firstBookingSlots` (`src/lib/server/reservation/first-booking-slots.ts`) and returns `firstBooking: null` once the member has booked. The slots run the booking flow's own rules (notice, tour, operating hours, closures, `bookableDateStrs` window), so the card never offers a start the form refuses. Not a second remote query, because `custom/no-concurrent-remote-queries` allows one per page (#3410). Not a dismiss button or table, because the first booking removes the card (#3410). Not the 3 soonest starts, because they land on one day at 15:00, 15:30 and 16:00 (#3410).
