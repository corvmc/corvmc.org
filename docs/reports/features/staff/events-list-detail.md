# Events list + detail

Status: ✅ Full CRUD

Two staff surfaces over one table, split by what staff do with a row. **Events** (`/staff/events`) is the staff's view of the public gig guide — every source, public statuses + `pending_review`, forward from today — where listings are moderated; its Posted by column names the accountable party (band chip, member, or plain CMC) and replaces the old Source column. **Productions** (`/staff/events?view=productions`, a view on Events since #2766) is `source='cmc'` at every status including draft, where a show is built: create, edit, poster upload, rebook detection, ticketing config, the room, the door. Its row carries two statuses side by side — the listing's (is it on the guide) and the production's (how far through putting it on we are) — plus the venue and a headliner-plus-count lineup summary, filterable by listing status, production status, venue and date range. A published CMC show is on both, in two roles; neither page is a subset of the other, since Productions holds drafts Events must never show. The `Productions` **page** is not the `Productions` **module** two rows down — that one adds run-of-show and settlement behind each show. The detail view is layered rather than branched: `/staff/events/[id]` is the general view for every source — facts, the bill, the lifecycle actions, and a two-hour window of what else is on — and sits at the address `entity-href` resolves every event ref to, so a staffer arriving from a shift or a notification lands on the least-privileged useful view. `/staff/events/[id]/production` is the console (full edit form, ticketing, ticket ledger, poster upload, the room, volunteer shifts) and redirects to the general view for a non-CMC row, so privilege is additive at the deeper path and gateable later without re-pointing every inbound link. See `docs/decisions/0007-the-canonical-event-url-holds-the-general-view.md`. Staff delete for rows that should never have existed (test events, duplicates, spam) — refused once any ticket exists, since cancel is the end state for those; releases the space booking, releases the poster and clears dangling flags. Recurring CMC events: weekly/biweekly/monthly series materialize independent draft occurrences (all sharing the prototype's poster — one R2 object, an attachment each, see `docs/decisions/0026-uploads-are-detached-and-swept.md`) via the daily generation cron; an occurrence reserves space only when the prototype holds a reservation, since its setup/teardown padding is derived from the prototype's; series badge + cancel on the detail page
