# Inbox

Status: ✅ /staff/inbox

Multi-channel thread list (contact form, member portal, email, SMS, Instagram, Messenger — the last two built and covered but not provisioned, both toggled off until Meta's app review clears; see `docs/architecture/meta-inbox-setup.md`). The Meta path files echoes as outbound so a DM answered from someone's phone stops reading as unanswered, dedupes on Meta's `mid` because deliveries are retried for 36 hours, gives a photo or story reply a placeholder body rather than dropping it, and blocks the composer's Reply tab past Meta's 7-day window with a note offered instead. Four views (Open/Snoozed/Resolved/All, with counts) default to Open, plus per-user saved views (`inbox_saved_view`) rendered as extra tabs. Filtering happens in a panel that takes the conversation pane so the list stays visible: status, inquiry type (`inbox_thread.subject` against the contact form's `contactSubjects` vocabulary, plus an Other bucket), assignee and a waiting-longer-than range, every option carrying the count it would leave. No Apply step — the list re-filters live and Done only closes. All filter state is in the URL, which is also what a saved view stores. Replying marks a thread awaiting reply (`inbox_thread.awaiting_reply_since`, cleared by any inbound message or status change, and settable by hand for answers given off-platform) — that moves it out of Open and into Snoozed, which holds everything parked — on a date or on a reply, with each row keeping its own badge — so the Open tab and the staff nav badge are the same number: what still needs a human. Open and Snoozed sort by longest waiting rather than newest first, and each Open row says why it is there — Unanswered (nobody here ever replied, `last_outbound_at` null), Replied (we answered and they came back) or Snooze expired (the wake cron returned it and left `snoozed_until` behind as the trace). Thread detail merges messages and internal notes into one timeline, with a single composer that toggles between Reply and Internal note (⌘⏎ to send); a note can hand the thread over in the same action, which posts it _and_ assigns it _and_ notifies the assignee. A collapsible details strip carries four columns — contact, history (previous conversations with the same address, first contact, source), this thread (messages, last reply, opened), and free-text tags (`inbox_thread_tag`, staff's own labels, distinct from the contact-form inquiry type). Open per thread, remembered in localStorage. One `DispositionBar` — Reply `⌘J` / Assign `⌘G` / Snooze `⌘S` / Resolve `⌘E`, chorded because bare letters were eaten by whatever had focus — is the only way a thread leaves the queue, and every disposition is reversible for ten seconds from its toast or with ⌘Z (`inbox_thread.undo_state`, a snapshot written by the same UPDATE that overwrites it). Snooze offers dated presets, a custom date, or "when they reply" — the conditional option, which is the awaiting-reply marker reached deliberately. Sending always carries a disposition: **Send + wait for reply** (the default, ⌘⏎), Send + resolve, or Send + keep open. `/api/cron/wake-snoozed` does both halves of the return trip — reopening due snoozes, and clearing any awaiting marker older than 7 days so a contact who never writes back cannot take a conversation out of the queue for good. **Daily** (`/staff/inbox/daily`) is a scoped one-at-a-time triage session started from the header: a start card breaking the Open set into unanswered / they-replied / came-back-from-snooze with a flat time estimate, a full-width focus card reusing the queue's own timeline and DispositionBar, `Skip` (not a disposition — the thread is untouched and moves to the end of the session), and a summary that hands the queue back by naming what is still open. Session state is client-side; only the day-stamp persists, in localStorage. Below `sm` the layout follows the design's mobile frames: Start Daily is a full-width action, the disposition row moves from the thread header to under the composer as three touch targets, and the three send options stack with the default first. With nothing open, the right pane shows the median time to a first reply per channel over the last 30 days of threads, derived from `inbox_message` on read, with the count of threads still waiting for one beside it (#2723).
