# Community listings

Status: ✅ Member-sourced events

Members author off-site listings for the public gig guide: draft → publish, with optional `event_band` lineup credits. A credited act that does not own the listing has a third reply beside accept and decline — **Request a correction**, which opens a portal thread with staff naming the act and the show, because staff can edit every listing and a complaint about somebody else's does not belong on an act-to-act channel. Publishing is direct until staff _uphold_ a report against one of a member's listings, after which their listings queue on `/staff/events`, badged `pending_review` (the calendar lists every listing unfiltered, so the pre-split `/staff/events?status=pending_review` link still lands correctly; `/staff/calendar` 308s here); staff approve or turn down with a required reason (`rejected`, stored on `event.reviewNotes` so the member can fix and resubmit), and restore trust from `/staff/members/[id]`. A dismissed report changes nothing — event reports are anonymous, so a bare accusation must not cost anyone their standing. `member_standing` at scope `community_event` holds the state; no row means trusted. CMC never sells these (`source !== 'cmc'`). Anyone can send an untethered "Event Tip" through `/contact`, landing as a normal web thread in the staff inbox. No feature flag. See `docs/decisions/0006-listings-publish-first-and-are-moderated-after.md`
