# Project templates

Status: ✅ /staff/tasks/templates

Reusable sets of work orders stamped into a project (#2034), the retired duty lists (`duty_list` tables kept, since a rename on prod D1 defaults to DROP). A Tasks setting, linked from the Tasks and Projects headers (#2385, #2767), read with `project.read` and edited with `project.manage`; `/staff/volunteer/duty-lists[/id]` 308s here. Anchors: the project's start, its earliest live event's doors/start/end (or the show it is applied from), and that event's production clock. Items land in the project's sections. Picked on New Project (#2387), or applied by hand ("Apply template" on a project, a committee's project, or the production console). `duty_list.project_kind = 'production'` marks the one template that starts a show: picking it creates the `production` row and committees with the project, and a show opened from a listing or a series stamps it too. The `production.created` auto-apply is gone; rules are the direction (#2389). Stamped rows copy `anchor` (#2033), so retime and close-out never read the template again. A missing anchor time stamps items unscheduled with a warning and `pending_offset_minutes`, placed by `placePendingWorkOrders` once the production time, event end or project start is set. Re-applying by hand needs a reason, audited on `project.duty_list_applied`; listeners refuse.
