# Recurring work

Status: ✅ /staff/tasks/recurring

Generate-on-close facility work — a monthly deep clean, a quarterly PA check. A `maintenance_schedule` names a role, an interval in days and optionally a project and an inventory unit (`asset_id`, copied onto each occurrence); its work orders carry `maintenance_schedule_id`. Resolving or calling off the open occurrence writes the next one **in the same `db.batch`**, unscheduled and due `interval_days` after the close, so nothing is stored ahead, no cron is involved, and a late close pushes the next one back rather than stacking it. A partial unique index (`uq_work_order_open_occurrence`) holds each schedule to one open work order, and the insert is `on conflict do nothing`, so a double close cannot pile up duplicates. Retiring a schedule stops the next one and leaves the open one queued. CMC's own permits, licenses and insurance policies are yearly schedules named "Renew <name>", with the issuer and reference in the notes; the Renewals module was removed (#2611, `docs/decisions/0063-renewals-are-recurring-work.md`).
